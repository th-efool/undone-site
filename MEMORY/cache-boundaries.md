# Cache boundaries and edge directives

- Discovery & Catalog: `/api/explore` sets `Cache-Control: public, s-maxage=60, stale-while-revalidate=300` on catalog hits, mock fallbacks, and DB queries. Uncaught errors omit caching headers.
- Feed: `/api/feed` enforces `Cache-Control: no-store` on all personalized and POST continuation requests to guarantee learner progress and exclusion isolation. Splitting required personalized reads (user progress, user cohort configs, channel prefs) from optional vector enrichment: any failure in required reads fails closed with HTTP 503 `Cache-Control: no-store`; failure in optional vector enrichment fails open gracefully to delivery vectors without failing the feed. Full catalog scanning is performed cursor-wise in batches of 100 lessons via `src/server/domain/feed/feedCatalog.ts`. Vector enrichment caching uses a deterministic SHA-256 key (`v2:<sha256>`) computed from sorted eligible chunk IDs. Obsolete process-local aggregate home/feed catalog caches are removed from read paths.
- Feed Continuation Protocol: POST `/api/feed` implements bounded exclusion pagination (`excludeChunkIds` capped at 5,000 IDs, 1 MiB max body size) replacing offset pagination. Revisit/replay requests prioritize explicit requestedChunkId at position 0 before heuristic scoring. GET requests with `pageIndex > 0` are rejected with HTTP 400 `FEED_CONTINUATION_REQUIRED`.
- Community: `/api/community/[cohortId]/channels` enforces micro-caching `public, s-maxage=15, stale-while-revalidate=60` with `Vary: Cookie, Authorization` for public cohorts. Private cohorts receive `private, no-cache, no-store`.
- Fast-fail Auth: `/api/cohort/publish` and `/api/community/channels/[channelId]/messages` validate session on line 1 before `req.json()` body streams or Zod validation to eliminate unauthenticated CPU burn.
- Payload compaction: `src/shared/lib/compactPayload.ts` recursively prunes null/undefined keys before JSON response serialization in `/api/feed` and community message endpoints.
- Chunk Progress Batching: `/api/progress/chunk` accepts single chunk updates or `{ batch: [...] }` / `{ updates: [...] }`. Validates accessible cohorts via Postgres `accessibleCohortWhere(userId)` in a single query, deduplicates in-memory by `${userId}:${chunkId}`, fetches existing progress via single MongoDB query, and persists using `UserChunkProgress.bulkWrite(..., { ordered: false })` to eliminate write lock contention.
- Debounced Activity Buffer: `src/server/infrastructure/logging/activityBuffer.service.ts` coalesces rapid user actions by compound key `${userId}:${eventType}:${entityId}` with sliding 3000ms window, atomic queue swap, and unref timer flushing, exposed via `/api/user/activity` with fast-fail auth.
- Session JWT Decode Cache: `src/server/infrastructure/auth/jwtCache.ts` provides worker-process in-memory LRU cache (2,000 entries max, 30s TTL bounded by cryptographic `exp`, SHA-256 token keys) hooked into NextAuth `jwt.decode` in `auth.config.ts`. Eliminates repeated AES-256-GCM decryption and HKDF key derivation on authenticated routes.
- User Permissions & Membership Cache: `src/server/infrastructure/auth/permissionsCache.ts` provides worker-process cache (5,000 entries max, 30s TTL, compound key `${cohortId}:${userId}`) for cohort enrollment and roles. Integrated into `/api/cohort/[id]/viewer` for <0.1ms responses, invalidated and synchronized in `/api/cohort/[id]/join` on member join/leave.
- Asset & LCP Priorities: `CohortHero.tsx`, mobile `ExploreHero.tsx`, `Logo.tsx`, `Hero.tsx`, `CollageLeft.tsx`, `CollageRight.tsx`, and `LearningSearchBox.tsx` inject `priority` and `fetchPriority="high"` on critical above-the-fold images and brand anchors to eliminate LCP delay.
- Typography Subsetting & Preload: `RootLayout` preloads primary brand typefaces (`Manrope`, `Geist`, `Geist_Mono`) with `subsets: ['latin']`, `display: 'swap'`, while deferring decorative fonts (`Caveat`, `Dancing_Script`, `Lora`, `Playfair_Display`) with `preload: false`. Injects `<link rel="preconnect">` and `dns-prefetch` for Google Fonts origins.
- Polling Tamer & HTTP 304 ETag: `useAssistantActivity.ts` pauses polling when `document.visibilityState === 'hidden'` and adapts poll interval between 2,000ms (active runs) and 20,000ms (idle runs). `/api/cohort-builder/workspaces/[workspaceId]/activity` and `/api/cohort-builder/workspaces/[workspaceId]/sources` cache workspace ownership in worker-process memory (60s TTL) and return `304 Not Modified` with 0-byte body on matching ETag, eliminating repetitive DB queries and SQL schema assertions. `StudyRoomScreen.tsx` and `/api/studyroom` pause 10s polling when tab is hidden, immediately refresh on visible, and implement worker-process `roomsSeeded` deduplication + 5s micro-cache with deterministic weak ETag, returning 0-byte `304 Not Modified` (<0.1ms) on matching `If-None-Match`, invalidated on POST join/leave.
- Client Query Debouncing & StaleTime Tuning: `useHome.ts` and `useExplore.ts` set explicit `staleTime: 300_000` (5m), `refetchOnWindowFocus: false`, and `refetchOnMount: false` to stop client refetch storms on window/tab blur-focus. `useCohortViewer.ts` disables window focus and mount refetching. `useHome.ts` cancels pending debounce timers (`reorderTimerRef`, `cohortTimers`) on unmount. `/api/user/cohort-config` converts $O(N)$ sequential cohort reorders to a single unordered MongoDB `$bulkWrite` command.
- Serverless Database Pool Capping: `src/server/infrastructure/db/postgres/client.ts` (`getPostgresPoolConfig`) detects serverless (`VERCEL === '1'`, `AWS_LAMBDA_FUNCTION_NAME`, `NODE_ENV === 'production'`) and dynamically caps pg pool to `max: 2` (vs 10 in dev) with 5s connection timeout, 10s idle timeout, and 15s statement timeout. `src/server/infrastructure/db/mongodb/client.ts` (`getMongoConnectionOptions`) caps Mongoose pool to `maxPoolSize: 2` (vs 10 in dev) with `minPoolSize: 0`, 10s idle reap (`maxIdleTimeMS: 10000`), 5s selection timeout (`serverSelectionTimeoutMS: 5000`), and `bufferCommands: false` to eliminate Neon/Supabase and MongoDB Atlas connection exhaustion in burst lambdas.
- Edge ISR Cohort Subpages & Revalidation: `/cohort/[cohortId]/archives`, `/cohort/[cohortId]/events`, `/cohort/[cohortId]/hall-of-fame`, and `/cohort/[cohortId]` use `getPublicCohort(cohortId)` with fallback to `PrivateArchives`, `PrivateEvents`, `PrivateHallOfFame`, converting from dynamic SSR to Edge ISR (`revalidate = 3600`). On public publish in `release/route.ts` and `publish/route.ts`, `revalidateTag(cohortTag(id), 'max')` and `revalidatePath` purge all 6 cohort subroutes + `/explore` + `/sitemap.xml`.
- 2-Tier SHA-256 AI Content Cache & Prompt Compression: `src/server/domain/cohort-creation/aiCache.repo.ts` (`getCachedAiResult`, `setCachedAiResult`) and `src/server/database/mongo/models/AiContentCache.ts` provide Tier 1 in-memory worker LRU (1,000 max entries) and Tier 2 MongoDB persistence (unique SHA-256 index, 90-day TTL). Hooked into `ChunkingService.semanticChunkTranscript` ('semantic_chunking'), `VectorScoringService.scoreTranscript` ('vector_scoring'), and `YoutubeObservationService.observeUnit` ('youtube_video_observation') to eliminate duplicate Gemini API calls and reduce LLM token expenses by 50–80%. `ChunkingService` resolves model dynamically from `process.env.COHORT_AI_MODEL || DEFAULT_COHORT_MODEL` (`gemini-3.1-flash-lite`), cutting per-token rates by ~60% over legacy `gemini-1.5-flash`. `src/shared/lib/aiPromptUtils.ts` (`pruneTranscriptWhitespace`) strips WebVTT/SRT timing arrows, numeric markers, HTML tags, and excessive blank lines before prompt injection and cache hashing, saving 25–40% input tokens.
- External Quota & Image Overage Tamer: `/api/import/youtube/metadata` caches video & playlist metadata in worker-process memory (2,000 entries max, 24-hour TTL) and attaches `Cache-Control: public, s-maxage=86400, stale-while-revalidate=604800` Edge CDN headers, protecting the 10,000 unit/day Google Data API quota. `LessonRow.tsx`, `CurriculumBoard.tsx`, and `CurriculumInspector.tsx` inject `unoptimized` on YouTube (`i.ytimg.com`) and Unsplash `<Image />` elements, streaming direct from upstream CDNs and bypassing `/_next/image` compute transformations to eliminate Vercel image overage costs ($5 per 1,000 images).
